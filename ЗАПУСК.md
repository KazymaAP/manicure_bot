# 🌸 Запуск бота manicure_bot

## Быстрый старт

### 1. Установите Python 3.10+
```bash
python --version  # должно быть >= 3.10
```

### 2. Установите зависимости
```bash
pip install -r requirements.txt
```

### 3. Заполните .env файл
Откройте файл `.env` и заполните обязательные поля:
- `BOT_TOKEN` — токен от @BotFather
- `ADMIN_IDS` — ваш Telegram ID (узнать: написать @userinfobot)
- `TIMEZONE` — ваш часовой пояс (например `Europe/Moscow`)

### 4. Запустите бота
```bash
python main.py
```

---

## Запуск через Docker

```bash
docker-compose up -d
```

## Исправления аудита v2 (дополнительные)

### 🔴 Критические (CRIT-01..05)
- **CRIT-01**: BackupService — оба sqlite3-соединения (src_conn И dst_conn) корректно закрываются в try/finally (было только dst_conn)
- **CRIT-02**: Race condition при переносе записи: сначала отменяем старую → создаём новую → при ошибке восстанавливаем старую
- **CRIT-03**: DatabaseManager.reset() теперь явно сбрасывает instance._initialized (иначе синглтон не пересоздавался)
- **CRIT-04**: delete_by_ids() передаёт tuple(appointment_ids) вместо list в sqlite3 (документированный интерфейс)
- **CRIT-05**: Broadcast рассылка запускается как asyncio.create_task() — не блокирует event loop; задержка увеличена до 0.04с (≈25 msg/sec)

### 🟠 Высокие (HIGH-02..08)
- **HIGH-02**: Имя мастера читается из config.json['master']['name'] вместо хардкода "Анастасия"
- **HIGH-03**: Запись config.json: asyncio.Lock + временный файл + os.replace() + cache_clear()
- **HIGH-04**: Валидация времени слотов — проверяет реальные значения (25:99 теперь отклоняется)
- **HIGH-05**: BaseRepository добавлено публичное свойство .db — заменяет getattr(repo, "_db") везде
- **HIGH-08**: Docker healthcheck заменён с curl на python (curl не установлен в python:3.12-slim)

## Исправленные баги (аудит v1)

### 🔴 Критические
- **BUG-C1**: `write_connection()` не существовал → заменён на `transaction()` + правильный SQL
- **BUG-C2**: Singleton reset() корректно закрывает все соединения
- **BUG-C3**: FOREIGN KEY для каскадного удаления слотов при удалении дня  
- **BUG-C4**: Regex валидации дат в admin_handler исправлен (`\\d` → `\d`)

### 🟠 Высокие
- **BUG-H1**: RateLimitMiddleware использует `isinstance()` вместо `update.message` (aiogram 3.x)
- **BUG-H2**: ReminderService получает `schedule_service` напрямую (не через getattr)
- **BUG-H3**: `SecretStr.get_secret_value()` для безопасного получения токена
- **BUG-H4**: `settings.health_port` вместо `os.getenv()`
- **BUG-H5**: `_safe_send` использует `isinstance(TelegramForbiddenError)`
- **BUG-H6**: `CronTrigger` с timezone для правильного часового пояса
- **BUG-H7**: Обработка `TelegramRetryAfter` (429 flood control)
- **BUG-H8**: Health server биндится на `127.0.0.1` вместо `0.0.0.0`
- **BUG-H9**: Пагинация записей (LIMIT/OFFSET)

### 🟡 Средние
- **BUG-M1**: `cancel_reminder()` использует `self._hours_before` вместо hardcode 24
- **BUG-M2**: `asyncio.to_thread()` для синхронных SQL-запросов
- **BUG-M3**: APScheduler + SQLAlchemy обновлены до актуальных версий
- **BUG-M4**: CalendarKeyboard с prefix поддерживает перенос записи
- **BUG-M5**: `transfer_cal_day:` (не `transfer_cal_date:`) для переноса
- **BUG-M6**: Адрес студии в напоминаниях
- **BUG-M7**: Валидация форматов date/time в CreateBookingDTO
- **BUG-M8**: Валидация структуры `services` словаря

- **BUG-M10**: `get_all_working_dates()` async-обёртка
- **BUG-M11**: `tzdata` в requirements

### 🔵 Безопасность
- **BUG-S1**: HTML-экранирование через `html.escape()` в admin_handler
- **BUG-S2**: LIKE-запросы экранируют `%`, `_`, `\` символы
- **BUG-S3**: METRICS_TOKEN для защиты /metrics endpoint
- **BUG-S4**: Лимит длины поискового запроса (100 символов)
- **BUG-S5**: Blacklist проверка в Path B (тесты)

### ✅ Архитектурные улучшения
- DI Container с явными зависимостями
- Дублированные scheduled jobs удалены (архивирование, проверка слотов)
- `AppointmentAlreadyCancelledError` отделён от `AppointmentNotFoundError`
- `BackupService` с sqlite3.backup API (hot-backup с WAL)
- Трекинг пользователей в таблице `users` для рассылки
- Уведомления waitlist через callback
- Управление уведомлениями (24ч/2ч/1ч) для каждого пользователя

## Структура проекта

```
manicure_bot/
├── main.py                 # Точка входа

├── requirements.txt        # Зависимости Python
├── pyproject.toml          # Метаданные проекта

├── docker-compose.yml      # Docker Compose
├── src/

│   │   ├── dto/            # Data Transfer Objects
│   │   └── services/       # Сервисы
│   ├── config/             # Конфигурация и DI
│   ├── domain/             # Доменные модели и исключения
│   ├── infrastructure/     # БД, репозитории, HTTP
│   └── presentation/       # Handlers, keyboards, formatters
├── migrations/             # SQL миграции
├── tests/                  # Тесты
└── data/                   # Данные (создаётся автоматически)
    ├── manicure_bot.db     # База данных SQLite
    └── backups/            # Автобэкапы
```
