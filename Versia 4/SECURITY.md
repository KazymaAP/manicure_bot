# Security Policy

## Supported Versions

| Version | Supported |
|---------|-----------|
| 4.x     | ✅ Yes    |
| < 4.0   | ❌ No     |

## Security Measures

### Secrets Management
- `BOT_TOKEN` хранится как `SecretStr` (Pydantic) — токен не попадает в логи/трейсбэки
- `METRICS_TOKEN` защищает HTTP `/metrics` endpoint через Bearer-токен
- Все секреты загружаются только из переменных окружения или файла `.env`
- `.env` файл **никогда** не попадает в Git (исключён через `.gitignore`)

### Input Validation
- Все пользовательские данные (имя, телефон, дата, время) валидируются на уровне DTO
- SQL-запросы используют параметризацию (no SQL injection)
- Специальные символы LIKE (`%`, `_`, `\`) экранируются при поиске

### Access Control
- Административные команды проверяют `user_id` в `ADMIN_IDS` перед выполнением
- Заблокированные пользователи (`blacklist`) не могут создавать записи
- Rate limiting middleware ограничивает частоту запросов (5 req/5s per user)

### Docker / Deployment
- Контейнер запускается от непривилегированного пользователя `botuser` (UID 1001)
- Health server биндится на `127.0.0.1`, не доступен из интернета

## Reporting a Vulnerability

Если вы обнаружили уязвимость безопасности, пожалуйста:

1. **Не создавайте публичный Issue** — это может раскрыть уязвимость до исправления
2. Отправьте описание через Telegram или email (контакты в профиле автора)
3. Включите в отчёт: описание, шаги воспроизведения, возможный impact

Ответ ожидайте в течение 48 часов.
